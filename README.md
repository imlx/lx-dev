# LX-DEV

确定性工程实施约束 —— 供 Claude Code、Codex、Cursor 等编程 agent 复用的工程纪律。

不是建议清单，是**硬约束**。每一条都来自真实项目的交付事故复盘：曾经踩过的坑，写下来变成判据，让下一个 agent 不再踩。

## 内容

| 文件 | 用途 |
|---|---|
| `lx-dev.md` | 完整规范：总则 + 方案/实施/验证/交付四阶段 28 条约束 + 反模式清单 + 检查清单。含完整判据、反例与证据要求 |
| `skills/lx-dev/SKILL.md` | 执行版 skill：精简为可独立工作的硬约束与硬门，供 Claude Code 等支持 Agent Skills 的工具自动加载 |

两份内容同源：`SKILL.md` 是 `lx-dev.md` 的执行子集，不引入新规则。规则变更先改 `lx-dev.md`，再同步 `SKILL.md`。

## 设计原则

1. **可判定**：每条约束都有「判据」——违反时能指出具体证据，不留解释空间。
2. **可验证**：每条约束都有「证据」要求——怎么证明遵守了，而不是靠自觉。
3. **技术无关**：不绑定语言、框架、业务领域。只约束「怎么做工程」，不约束「用什么做」。
4. **失败驱动**：每条都对应一次真实事故（截断字段让数据消失、只在当前页筛选、页面不报错但控件缺失、增量测试假绿等）。
5. **不制造流程**：优先单批次交付；阶段化只为控风险，且每阶段自动验证、自动推进，人只做最终验收。

## 安装

### Claude Code

```bash
git clone https://github.com/imlx/lx-dev.git
cp -r lx-dev/skills/lx-dev ~/.claude/skills/        # 全局可用
# 或
cp -r lx-dev/skills/lx-dev <your-project>/.claude/skills/   # 项目内可用
```

安装后，涉及写方案、修 bug、重构、改数据库、提交前的任务会自动加载该 skill。

### Codex / Cursor / 其他 agent

把 `lx-dev.md` 全文并入项目根 `AGENTS.md`，或作为系统提示/规则文件的核心章节：

```bash
# 仓库根已存在 AGENTS.md 时，追加分隔线后拼接
printf '\n\n---\n\n' >> AGENTS.md
cat lx-dev.md >> AGENTS.md
```

也可只取第 7 节检查清单做人工评审用。

### 与项目本地规范共存

- 冲突时**从严者优先**；本地规范写明豁免理由的条目按本地规范执行。
- 建议在本地规范中显式声明：`本文件未覆盖处按 LX-DEV 执行`。
- 编号可直接用于评审意见：`违反 B2`、`V7 未取证`。

## 约束速览

| 阶段 | 编号 | 核心 |
|---|---|---|
| 总则 | G1-G3 | 证据优先 / 信息不减少 / 根因而非症状 |
| 方案 | P1-P5 | 标准先行 / 必做与不做两栏 / 七视角不限轮次自检 / 少分阶段自动推进 / 冲突上报 |
| 实施 | B1-B9 | 先定位 / 禁止降级式修复 / 三同步 / 契约稳定 / 迁移逆命题断言 / 错误统一 / 单文件单写入者 / 密钥不入库 / 界面十条 |
| 验证 | V1-V9 | 全量测试 / 真实链路 / 门禁全绿 / 诊断清零 / 覆盖如实 / 独立复核 / 三件套 / 重启即交付 / 手段不可互替 |
| 交付 | S1-S5 | 提交原子 / 信息可回溯 / 文档同步 / 变更留痕 / 四段汇报 |

## 六个不可跳过的硬门

根因门、降级门、全量门、真实链路门、独立复核门、三件套门。任一门未过，不得宣称完成。
